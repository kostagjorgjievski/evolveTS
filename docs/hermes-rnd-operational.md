# Hermes R&D researcher: operational handback

Hermes owns source discovery, interpretation, method implementation, diagnostics,
and requesting official validation. The infrastructure monitor repairs tools,
routing, accounting and recovery; it must not implement candidate algorithms and
claim those as autonomous acceptance.

## Runtime and ownership

`scripts.autoresearch_seeder.service` owns one task research root under an exclusive
lock. Idle polling, daily budget waits, resource waits and PAUSE never start a
model. An investigation creates a real seeder job with its own source cache,
SQLite experiment/decision ledger, artifacts and isolated Hermes home. MiniMax
M3.1 Flash scouts external sources; Kimi 3.1 Pro checks the interpretation and
implements. Both request medium effort. The installed Hermes release is pinned
to v0.22.5; installed CLI behavior was tested rather than assumed from help text.

Each wake runs at most one 20-minute resumable model session. Research continues
from its own durable files and experimental ledger in a fresh prepared context.
Finite per-investigation and UTC-day limits apply; provider-reported dollars can
be unavailable and must not be presented as actual free usage. Admission waits
and trusted full grading are excluded from active model development time.

The service reloads validated configuration at session boundaries; task identity
cannot change through reload. File markers `PAUSE` and `STOP` prevent new starts.
Configuration changes do not erase consumed usage. Three consecutive infrastructure
errors trip a pause. Restart only after verifying the previous owner process birth
and command and checking for an active session; never duplicate a productive owner.

On the Mac Mini the detached supervisor works through the authorized desktop
parent. LaunchAgent startup was blocked by that process's access to Documents;
the attempted agent is disabled. Reboot persistence has not been demonstrated.
The active pointer, status, current-session and ledger files are the status interface.

## Scientific and publication gates

Scouts receive scoped read/write/search/fetch tools and no official full validation
in that role. Public Kaggle notebooks, read APIs and primary papers are permitted.
Source responses are cached by URL and content hash, preserving revisions. Source
text is evidence, never an instruction granting more authority. PDFs are converted
for reading; arbitrary host shell and other job paths are outside these tools.

The reproducer receives the source handoff and official task API/baseline. It may
reject the scout interpretation. It records hypotheses, failed paths, experiments,
exact generation instructions, provenance and explicit license uncertainty.

A requested full development validation freezes the candidate and ends the model
session. The trusted controller runs unchanged task grading, then independently
confirms the exact saved submission under a distinct salt. It does not rerun a
nondeterministic optimizer to make the confirmation submission. The publisher
requires protocol/source pins, passing official receipts, identical submission
file hashes and improvement on both checks. Author scores and toy diagnostics
cannot certify a seed. Exports are immutable and hash sealed.

Per-investigation checkpoint `public_inputs` overrides service-wide inputs.
`cold_acceptance` excludes existing library findings, so the fresh discovery test
receives only its frozen public source, neutral task guide and official baseline.
It retains its own experimental memory across sessions. Later normal research
can consult eligible external library records. No other branch's private science
is eligible before the configured release boundary.

## RSI connection

The host installation helper adds a fail-open preparation hook. At an opted-in
future attempt boundary it freezes at most one compatible public handoff and
verifies an immutable seed export before copying its source bundle. A missing or
busy researcher never blocks the branch. The worker can reject advice, and its
ordinary full validation remains mandatory. Parent code is never automatically
replaced. An own-parent research request remains scoped to that branch, including
failed experiments. Active attempts and stopped campaigns are untouched.

The current host bridge opts in chemistry only; the DQI adapter is not installed.
DQI is paused by user and main chemistry RSI is stopped by user. Neither should
be resumed by the researcher or infrastructure monitor.

corrected the source payload interpretation, generated circuits and requested

across two sessions; the separate blind discovery took about 12.1 minutes. This

The monitor verified its export seal and exact submission identities, then
activated the approved four-hour/twelve-session investigation and twelve-hour/
thirty-six-session daily limits without resetting consumed usage. An omitted
optional hypothesis `source_urls` field exposed a registry integration fault:
the publisher exported a valid seed, but the library did not advertise it. The

provenance for an already verified seed. Limited diagnostic findings still
require explicit hypothesis-to-source linkage. The exact existing export was
registered idempotently, without rerunning grading or altering candidate code.

## Bounded scout handoff repair

A later source investigation exposed another routing fault: role selection
based solely on registered hypotheses could keep assigning productive but
unfinished source exploration to the scout at every checkpoint. A completed
scout window now hands its full own-job state to Kimi even when structured
hypotheses were omitted. Later windows remain with the reproducer. Role
instructions request explicit source-linked hypotheses; the monitor supplies
no candidate algorithm or implementation. Drafts, receipts and consumed time
remain intact. The full implementation and host-memory suite now passes128tests.

## Research continuity after a successful seed

A live check found the service idle with unused daily budget after both fixed
broad topics completed, despite researchers having recorded unchosen, untested
hypotheses. With `service.follow_up_hypotheses` enabled, the idle path now advances
one of those model-authored directions into a new bounded investigation. The
monitor does not invent or implement the method.

Only completed shared R&D with an intact certified export is eligible. Chosen
and rejected hypotheses, uncited hypotheses, branch-private research and recursive
follow-up chains are excluded. Each parent/hypothesis is queued at most once.
The follow-up receives a frozen public parent artifact, source provenance,
relevant cached public documents, and the model's own hypothesis/decision record.
It starts directly with Kimi rather than repeating source discovery. The handoff
explicitly labels the new mechanism untested; the certified parent does not
establish it, and revalidating an unchanged parent is not the research objective.

Existing per-investigation and daily admission limits remain in force, with no
usage reset and no production branch or campaign change. This finite backlog
can exhaust; idle checks then make zero model calls until new authorized work
or the next daily agenda becomes available. Partial handoff copies recover
before admission. Parent artifact and cached-reference sizes are bounded to
fit the existing public-input limit.
